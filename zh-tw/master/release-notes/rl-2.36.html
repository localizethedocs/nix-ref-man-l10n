Nix 2.36.0 Reference Manual

Release 2.36.0 (2026-11-16)

Packaging

  • Starting with this release, nix-installer binaries are shipped alongside other binary artifacts in releases.nixos.org.

    You can run the installer with:

    curl -sSfL https://channels.nixos.org/nix-latest/nix-installer | sh -s -- install

    It’s built for x86_64-linux, aarch64-linux and aarch64-darwin platforms and only supports multi-user installations.

  • Cross-built binary releases for powerpc64-linux and powerpc64le-linux platforms #16274

  • Scripted installer supports busybox-based systems (e.g. Alpine) in single-user mode #16537

  • The scripted installer sets the correct store mtime #16558

Improvements

  • Daemon worker spawning rework #15857 #16659

    Previously, nix-daemon accepting on the nix-daemon.socket would spawn a worker process by fork()-ing without calling execv*. This has historically been a source of issues around fork-unsafe dependencies and in Nix itself. The most notorious instance of this issue has been Nix on macOS, which discourages such use of fork(2), and has caused numerous issues in the past (mostly around the use of SecureTransport TLS backend in libcurl and aws-c-io).

    Now nix-daemon spawns a worker processes by spawning and executing itself in --stdio mode by redirecting stdin/stdout to the accepted socket and forcing the trust level with the stabilised --force-trusted and --force-untrusted flags. The path to the current binary is either /proc/self/exe on Linux, acquired via _NSGetExecutablePath on macOS, or KERN_PROC_PATHNAME sysctl on FreeBSD.

    No functional changes are expected from this, though there are minor user-visible behavioral changes:

    • nix-daemon no longer needs to be restarted for /etc/nix/nix.conf changes to take effect in the daemon worker (note that this doesn’t apply to settings like allowed-users or trusted-users).
    • The command line of the worker process no longer has the form nix-daemon <peer pid>. Previously, the PID of the daemon client process was inserted into argv[1]. This also obviates the need for passing the no-op --daemon flag for making room for the PID in argv[1]. The peer PID is now part of the argv[0] in the form of nix-daemon.worker-<peer pid>. This is an internal debugging feature used for correlating the daemon worker process with its client.

  • daemon-trust-override, --process-ops stabilisation #16637 #16659

    daemon-trust-override experimental feature has been stabilised. This change was needed to facilitate the daemon worker spawning rework.

    --force-untrusted now behaves correctly when the --stdio daemon worker’s store is another remote store backed by another daemon.

    --force-untrusted, --force-trusted, --default-trust, --process-ops flags accepted by nix-daemon and nix daemon are no longer experimental.

  • Daemon enables cgroup controllers for build cgroups #9675 #16024

    With use-cgroups, the daemon now enables the cpu, memory, io and pids controllers in its cgroup’s cgroup.subtree_control, so per-build cgroups expose memory.peak, io.stat etc. instead of only cpu.stat. This requires the controllers to be delegated to the daemon’s cgroup (e.g. systemd Delegate=yes).

  • Nix now finds Darwin runtime garbage collector roots without lsof #3011 #13990

    On Darwin, the garbage collector now uses libproc to retain store paths referenced by running processes through their working directories, open files, mapped regions, or environment variables. This avoids the slow lsof fallback and adds environment-variable roots, which lsof could not discover.

    macOS does not expose the environment variables of entitled binaries while System Integrity Protection is enabled, so those roots remain unavailable.

  • nix run, nix search and nix bundle now auto-call functions #5316 #15895

    If an installable given with --file or --expr evaluates to a function, it is now called automatically, provided each of its arguments has a default value or is passed with --arg/--argstr. This makes nix run, nix search and nix bundle behave like nix build, nix shell, nix-build and nix-env --query.

    For example, nix run --impure --expr '{ pkgs ? import <nixpkgs> {} }: pkgs.hello' now works instead of failing with error: attribute 'type' does not exist.

    nix eval and nix edit, which show the value itself rather than a package, are unchanged.

  • Build cgroups are named after the derivation #16516

    Per-build cgroups are now named nix-build@<drv-hash>-<uid> when a build user is used, and nix-build@<drv-hash>-<pid> otherwise. They replace nix-build-uid-<uid> and nix-build-pid-<pid>-<counter>, so external tools can locate the cgroup of a given derivation’s build.

  • Add an alias for optimise. #1902 #11326 #11577 #15997

    Add “optimize” as a linguistic variation of “optimise”. Now both the nix-store and nix store commands work with the same spelling.

  • Downloads and store path copying produces significantly less log updates for internal-json logger #16671 #16670

    Tools such as nix-output-monitor were previously significantly bottlenecked parsing on the order of tens of MB/s of JSON. Download progress updates are now chunked and rate-limited. Bandwidth requirements for the logger are now significantly lower.

  • Styled output on stdout is plain when stdout is not a terminal #4626 #9486 #16710 #16711

    nix profile list, nix profile history, nix flake metadata, nix flake show, nix search and nix store diff-closures no longer write ANSI bold and color to stdout when it is not a terminal, or when NO_COLOR is set. Set CLICOLOR_FORCE to keep the styling.

  • Add nix version command with --json option #16201 A --version flag is more like a modern subcommand than a flag, and this provides a place for JSON output, making it easier to consume in scripts. When --json is passed, the output includes library versions.

    nix --version -vv output also includes library versions in human-readable comma-separated format.

  • Bash completions now handle redirections #16648

    File names after redirections (e.g. nix log nixpkgs#hello > /tmp/hello-lo<TAB>) can now be completed.

  • Nix now makes use of reflinking via copy_file_range when copying files on filesystem that support it #15410

Error message improvements

  • Start of infinite recursion is now visible #16296

    When Nix reports a trace for an infinitely recursive evaluation, it will now let you discern the cycle from the code that leads up to the cycle.

    Example:

    nix eval --expr 'let f = builtins.add f 1; in toString f' --show-trace

    error:
       … while calling the 'toString' builtin
         at «string»:1:30:
            1| let f = builtins.add f 1; in toString f
             |                              ^

       … entering the infinite recursion

       … while calling the 'add' builtin
         at «string»:1:9:
            1| let f = builtins.add f 1; in toString f
             |         ^

       error: infinite recursion encountered

  • builtins.warn now supports unindented multi-line messages #14794

    builtins.warn now preserves the formatting of messages that start with a newline instead of adding indentation to align them with the warning prefix.

  • builtins.addErrorContext keeps the error from value when context fails #8283 #16618

    If evaluating context in builtins.addErrorContext context value fails, the error from value now propagates, with the error from context in its trace. Library authors can therefore use more complex context expressions without the risk of hiding the error from value.

    addErrorContext can no longer be abused to catch uncatchable errors like abort.

  • Error traces now show both the selection site in addition to the definition site when an attribute is retrieved and both locations are known. #16249

  • Error traces now always show the derivations that were getting instantiated #16282

  • All operators in error traces are displayed, and consistently #16301

  • Error messages for interrupted downloads are more concise #16095 #16646 #14757

Bug fixes

  • nix develop no longer disables ASLR on Linux #16624.

    Previously, nix develop would enable ADDR_NO_RANDOMIZE personality bit. This disabled ASLR for all subsequent commands run in the devshell.

    Additionally, impersonate-linux-26 setting has been removed. If you require this, you can change the personality manually or use deterministic-uname from Nixpkgs depending on the use-case.

  • File descriptors are more reliably closed in children processes #16247 #16717 #16749

    Also, Nix daemon no longer performs 1 million close syscalls (commonly configured RLIMIT_NOFILE for the daemon) for each spawned derivation builder on macOS by relying on libproc for closing file descriptors in the child.

  • post-build-hook is no longer run in a mount namespace with a writable Nix store #16247

  • builtins.pathExists no longer swallows access errors from evaluating its argument #16728

    Since Nix 2.20, builtins.pathExists accidentally recovered from access errors caused by evaluating its argument. Consider:

    $ nix eval --expr 'builtins.pathExists (builtins.readFile /etc/passwd)'

    This evaluated to false, even though builtins.readFile /etc/passwd would throw, and builtins.pathExists never saw a supposed path.

    Now the error propagates, as it did in Nix 2.19 and earlier. This invocation fails with the same error observed by calling builtins.readFile /etc/passwd in isolation.

  • Store garbage collector can now delete App bundles on macOS #16626 #16719

    Previously, even when run as root Nix attempted to make directories writable for deletion, which is not allowed for App bundles on macOS and would fail with Operation not permitted. Nix now skips the chmod when run as root on macOS.

    Additionally, when run with DAC_OVERRIDE capability on Linux, chmod operation is also skipped.

  • nix eval --write-to is stricter about what it writes #16760

    nix eval --write-to now requires attributes to correspond to a single file name. In particular, it rejects attribute names that contain / or are empty, in addition to rejecting . and .. as it did already. Previously, an attribute such as { "a/b" = "..."; } was written to a nested path a/b, which is a bit of an “injection”.

    Attribute sets can also now be nested at most 64 levels deep, the same limit as for NARs.

    (The output is also now written in the same way as NARs are unpacked, which hardens it in a bunch of ways.)

  • Path-like flake references detect Mercurial checkouts

    A path-like flake reference such as . used to become a git+file: input only inside a Git repository, and a path: input everywhere else. In a Mercurial checkout that copied the whole directory to the store, .hg and untracked files included, and the flake had no rev.

    Such a reference now resolves to hg+file:, so only tracked files are copied. This needs the hg executable, as hg+file: inputs always did.

    Input schemes, including ones from plugin-files, can resolve a path-like flake reference to their own scheme by implementing InputScheme::localRepoURL().

  • S3: endpoint=host:port fixed, deprecated in favour of full URLs

    Bare host:port values for the endpoint parameter of s3:// store URLs were misparsed (the host was taken as a URL scheme). This is fixed, but the bare form and the separate scheme parameter are deprecated: use a full URL such as endpoint=https://minio.example.com instead.

  • Boost.Context bug causing incorrect daemeon exception detection has been worked around in Nix and Nixpkgs, with a fix contributed upstream #16197 #16174.

    This would cause spurious aborts in nix repl when builtins.toFile or other primops that fetch to the store failed. It only affected builds of Nix using Boost’s fcontext coroutine backend with libstdc++ standard library.

  • NUL bytes in derivation builder and args attributes are rejected #16245

    This issue was not possible to encounter from the Nix evaluator, since Nix strings disallow embedded NUL bytes but could lead to silent truncation in other cases.

  • Derivation parser is now more strict #16237 #16284

    The derivation ATerm parser now rejects derivations that are not in the form that’s produced by the evaluator.

  • The NAR parser is stricter when file contents are discarded #16325

    When computing the NAR listing (.ls files) and other operations that discard contents of regular files in NARs, Nix did not sufficiently validate padding bytes.

  • Store path basenames that don’t have the hash part followed by - are properly rejected #16257.

  • Truncated Brotli compressed NARs no longer cause Nix to loop infinitely #16575.

  • Errors while writing to compressed streams (e.g. copying to a local binary cache store) no longer cause a crash #16664

  • Non-lexically-canonical home-path literals (e.g. ~/repos/nixpkgs/.) no longer crash the evaluator #16651

  • Deleting profiles with unexpected mtime no longer triggers a crash #16634

  • Internal source tree names no longer leak into evaluation results of builtins.toXML and value printing #16780

    This is a regression from 2.32 for pure-eval mode, which is now fixed.

  • builtins.readDir builtins.storeDir no longer fails in impure evaluation mode #16780

    Since 2.32, it would fail with error: path '/nix/store/' is not in the Nix store.

  • Logging has been hardened against crafted inputs #16784 #16456

    Nix now handles malformed inputs from derivation builders more robustly and warns on unknown activities and result types.

  • While reading git objects, Nix now rejects duplicate Git tree entries and unsorted trees #16793

ca-derivations

  • Add new nix store build-trace delete command #15655

  • Implement new builder-rpc-v0 feature; see #15793 below under dynamic-derivations. While motivated primarily by the dynamic derivations feature, registering outputs is also useful for content-addressing derivations. The builder can learn the calculated content-addressed path of one of its outputs before creating others, removing the need for any rewriting on the nix-daemon side after the derivation finishes.

  • Error instead of crashing when realisations cannot be queried #16014

dynamic-derivations

  • Implement new builder-rpc-v0 feature #15793 This PR adds support for creating new store objects within a derivation at runtime, then registering them as an output.
  • nix store add --scan for creating references, as well as in builder-rpc-v0 #16163

C API

  • Expose evaluator helpers for working with derivation trees #15842 nix_get_derivation, nix_value_auto_call_function
  • Fix nix_get_external #15954
